# Design foundations

Read the chosen design style and user references. Business, playful, glass, editorial and other
directions are all valid; do not substitute personal aesthetic defaults. Identify the audience,
main task, information density and content before choosing typography, spacing and colors.

Record a compact design contract: semantic surface/text/accent/status colors; typography roles;
spacing scale; border/radius/shadow rules; navigation; responsive behavior; loading, empty, error
and success states. Preserve an existing system unless the user asks for a redesign.

Keep accessible contrast, keyboard operation, visible focus, meaningful labels and sensible motion
across every style. Test actual text over every translucent surface. Funky layouts still need
clear reading order. Restrained styles still need hierarchy and personality. Do not blindly copy
another brand's identity or include images that do not support the content.

Inspect narrow and desktop renders with realistic content. Check zoom, long labels, tables,
menus and touch interactions. Give the Builder concrete component/state decisions and visual
references. Report the screenshots or previews actually inspected, not imagined visual quality.
